## E3: Kaleido's defines

The change, recorded as [`e3-define.patch`](e3-define.patch) (GPL-3.0, from the scratch branch):

- `configure.py` takes `--define NAME[=VALUE]` (repeatable). The defines join the version's (`BLACK2`) for the C
  compiler (`-d`) and the assembler (`-D`). Any define turns the build into a non-matching one, as `--bugfix` and
  `--shift` do, and a regeneration keeps them.
- `src/ov167/btl_calc.c`: `BtlCalc_RollCritical` returns TRUE under `#ifdef KALEIDO_E3_ALWAYS_CRIT`.

**Verified**:

| Check | Result |
| --- | --- |
| Switch off: `configure.py b2_us && ninja` (every matching check) | passed; SHA1 `e51e6dfb8678a3d19dcd2a10691b96a569ca0abb` (300 s) |
| Switch on: `configure.py b2_us --define KALEIDO_E3_ALWAYS_CRIT && ninja build/pokeblack2_us.nds` | built (566 s; every C file recompiled, since the define changes every compile command); no compiler warnings |
| Compiled `BtlCalc_RollCritical` | `movs r0, #0x1; bx lr` (was a table lookup, a call to `BattleRandom` and a compare) |
| Overlay 167 | 268,096 → 268,064 B (−32) |
| Overlays whose load address moved | 15, including 168 (battle display), 171 and 285–290 |
| `OV290_BSS_END` | `0x21fd080` → `0x21fd060`: the DS-mode arena grew by 32 B (E6) |
| DSi digests (`verify_dsi_rom.py`) | intact |
| Test ROM SHA1 | `84a0a726340c11b6943b8fb663c37c4849dc689c` (with E1 and E2's changes) |

What this settles:

- The rule from ADR 0002 works in practice. A behavior change behind a `KALEIDO_` define leaves the matching build
  untouched, so the baseline stays a regression check.
- A code-size change moves overlays, so the build is a real test of upstream's shift safety (`docs/configs.md`).
  The battle in game (pending) is the proof that nothing broke.
- Each switch combination is a full recompile (about 10 minutes here). CI's compile job per define set
  (`06-testing.md`) must budget for that.

## E1: text

`res/text/system/game_start.txt`:

```
GameStart_Text_HiThereWelcomeWorld = Kaleido E1: é ♂ ♀ ★ ♪ …{be01}\nThis line is long on purpose, to show where the text box ends.{be01}
```

- é, ♂, ♀, ★ and ♪ all appear in B2W2's own system text (3,442, 6, 7, 1 and 166 times). "…" (U+2026) appears nowhere
  in it.
- **Verified**: the text packer accepted the whole line, "…" included.
- **In game** (owner, 2026-11-03): the new text shows. Still to confirm: whether every symbol, "…" especially, draws
  as a glyph rather than a blank or box, and whether the long second line wraps, clips or overflows. Both decide how
  FireRed's text is converted (R-11).
