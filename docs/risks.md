# Risk register

Last reviewed: 2026-11-03 (planning pass, updated with the owner's answers to Q1–Q10). Review at the end of each phase
and whenever an experiment finishes.

- **Severity**: what happens if the risk occurs. High = blocks a Tier 1 game or forces an architecture change;
  Medium = large rework or a fidelity loss; Low = local cost.
- **Likelihood**: High = expected or already observed; Medium = plausible; Low = unlikely.
- **Retired by**: the experiment or decision that closes it (E-numbers in `docs/plan/05-roadmap.md`, Q-numbers in
  `docs/plan/07-open-questions.md`). A retired risk stays listed with its outcome.

| R-27 | **Changes to ARM9 main need the DS ARM7 BIOS at build time.** Moving any code in ARM9 main changes bytes in its first 16 KiB (E4a). So can a same-size data change: the ROM stores ARM9 main compressed, and its compressed end is a word in the first 16 KiB (E9). Either way dsd must recompute the DSi secure-area values with the BIOS's Blowfish key, and refuses otherwise. Overlay-only changes aren't affected (**Verified**, E4a, E9). | Medium | Low (mitigated) | ADR 0004: Kaleido's dsd change `--allow-stale-secure-area` builds without the BIOS and keeps the stale DSi values (**Verified**: E4a's ROM builds, the untouched pin still matches); `--arm7-bios` when a builder has one; Tier 1 reuses zone IDs. | R-28 | **Incremental builds can link stale objects.** Upstream's depfiles name generated headers by absolute path, the rules that write them by relative path, so ninja treats them as two files. In the field, heap 1 has 288,256 B left for everything else. | High | Medium | Validator arena check on every build (`0x023e0000` − `OV290_BSS_END` ≥ fixed heaps + margin); new code in overlays that replace B2W2 ones; B2W2 systems switched off per game (Q7) free space; E6b measures runtime free memory and the overhead. | E6b + the first engine patches |
